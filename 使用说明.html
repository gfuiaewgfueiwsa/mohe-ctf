01这是什么

把一个文件拖进窗口，它先判断这是什么文件，再把能用的分析链依次跑一遍；遇到压缩包、图片、镜像里再套着文件，就继续往下拆，直到找到 flag，或者明确告诉你没找到。

面向前两类场景：CTF 比赛与靶场练习、电子数据取证教学。双击是无界面参数时的图形模式；也可以用命令行批量分析，或者交给 RAC 自动化直接从题目描述走到提交。

整包随带 Python 3.11.16、JRE 21、Node 22 三套运行时，以及从压缩工具到反编译器的便携工具。复制到另一台 Windows 电脑就能用，不需要先在系统里装 Python 或 Java。

先看清边界。软件每次启动都会要求你确认「仅在 CTF 比赛授权范围内使用」。这个勾选是自我约束，不构成任何网站的测试授权。具体边界见第 12 节。

自动化逆向与 Pwn（2026-11-07）

自动逆向：文件分析或 Web / Pwn 页的“自动逆向分析”会依次跑字符串抽取、强 flag 正则、可疑符号、radare2 复核； .pyc 自动反编译，UPX 壳自动脱壳。命令行等价入口 魔盒-ctf.exe --cli <文件> --ctf-only， 结果写 workspace\cli_report.txt。

Pwn：--pwn chal.elf --ctf-only 做静态定位（win 函数、/bin/sh、pop rdi;ret 等 gadget、保护机制）； 补 --host、--port、--offset 即拼 payload 连远端并抓 flag。 GUI 走“选择 ELF 并 checksec”→“自动逆向分析”→填 IP/端口/偏移→“ret2win 一键打通”；不填偏移按 40/48/…/128 逐个试。

边界：偏移必须实测（cyclic 200 + 崩溃现场），工具不猜偏移；只覆盖有直白 win 函数的 ret2win， 无 win 时给 ret2libc 思路，ROP 链仍需按 libc 版本人工拼；不内置反弹 shell、不做持久化。

本轮实测：合成 PE 的后缀 flag 被自动逆向命中；ELF 样例输出 gadget 与 ret2win 模板；本地 TCP 闭环偏移 64 抓到 flag{ret2win_9137}（PWN_SMOKE=PASS）；Web 回归 21 项全过。

02快速开始

  1. 01
    双击 魔盒-ctf.exe

    首次启动会加载 OpenCV、scapy 等组件，比之后慢几秒，属正常。

  2. 02
    勾选授权确认

    必须主动勾选后才能进入主界面；拒绝或直接关闭确认窗，程序退出。

  3. 03
    拖入题目文件

    可一次拖入多个，自动排队逐个分析；也可以点「选择文件」再点「开始分析」。目录和失效路径会被提示忽略。

  4. 04
    看结果

    分析报告里的红色行即 flag；「提取的文件」列出拆出来的新文件，已自动递归分析；实时日志记录完整执行过程。

  5. 05
    留档

    点「导出报告」，结果静默写入软件目录下的 reports\，同时生成 HTML 与 TXT，不弹保存框。

04RAC 自动化

RAC 是 v2.4 的主功能，把「读题 → 找脚本 → 填参 → 跑 → 拿 flag」压进一条流水线。名字来自三段式：Recognize、Assemble、Command。

识别认的是题面里的结构化信息：RSA 的 n、e、c、p、q、d、dp、dq（支持 0x 十六进制），host:port、URL、MD5/SHA1/SHA256、Base64 与 Hex 密文、账号口令、flag 前缀。给出 p、q 时能自动推 n；附件会走一遍深度分析，解码出的文本再回来补一次参数。

装配不靠猜：脚本头注释、argparse 参数表、PARAMS 参数字典都会被 ast 解析，并检查依赖是否可用。评分最高的几个候选进入队列。

执行按脚本接口自动填参（--params 参数文件、argparse 命令行、或原样执行），失败自动降级下一个候选；交互式脚本以 EOF 优雅退出，不会把界面卡死。GUI 里红色高亮 flag，CLI 直接写报告。

08命令行用法

无参数双击是图形界面。批量场景用下面两条命令，都要带 --ctf-only 作为授权声明，否则程序直接退出。

:: 批量分析文件
魔盒-ctf.exe --cli <文件> [文件...] --ctf-only

:: RAC 自动化：题目描述 + 附件
魔盒-ctf.exe --rac "题目描述" [附件...] --ctf-only

:: Web 一键自动取证（只读）
魔盒-ctf.exe --webauto "http://靶机:端口/路径" --ctf-only

:: Web 深度全自动（分析 + 全 payload 矩阵 + 上传测试 + 取 flag）
魔盒-ctf.exe --webattack "http://靶机:端口/路径" --ctf-only
参数说明
--cli / -c批量分析，报告写入 workspace\cli_report.txt。
--rac跑 RAC 流水线，报告写入 workspace\rac_cli_report.txt，末尾附提取到的 flag。
--webauto对单个 Web 题目地址跑一键自动取证（只读），报告写入 workspace\webauto_report.txt，JSON 明细落 reports\。
--webattack / --deep深度全自动：页面分析 → 六类漏洞全 payload 矩阵 → 上传点三形态载荷 → 定向取 flag → 接力 sqlmap。报告写入 workspace\webattack_report.txt，JSON 明细落 reports\webattack_*.json。
--ctf-only必需。声明只处理本次比赛的授权题目。

命令行模式同样会把中文输出切到 UTF-8，避免控制台代码页导致乱码；报告文件本身始终是 UTF-8。

09报告、导出与日志

目录存什么
reports\「导出报告」生成的时间戳命名 HTML 与 TXT。Web 检测的 JSON 报告也在这里。报告里的 URL 与正文可能带题目凭据，对外分享前先看清。
exports\媒体中心的产物：视频抽帧、截图、GIF、语谱图、波形图、派生音频、图片增强图。
workspace\分析中间文件、修复与雕刻输出、rac_runs\ 全过程记录。删除它不会影响程序，下次启动自动重建。
workspace\crash.log异常日志。启动时先写一行会话头，正常情况不会出现堆栈；真出问题时把整份日志发给开发者。

程序不会把分析结果上传到任何地方，也没有联网回传。RAC 与 Web 检测是否发请求，取决于你在对应页面填的目标。

10一键卸载

  1. 01
    先关外部工具

    Ghidra、x64dbg、dnSpy、MobaXterm 若已打开，先自行退出，避免文件占用删不干净。

  2. 02
    双击 卸载魔盒-ctf.bat

    窗口会说明将要删除的范围，并显示当前文件夹路径，逐项核对。

  3. 03
    输入 Y 回车

    程序先结束 魔盒-ctf、ffplay、ffmpeg、ffprobe 进程，再交给后台脚本静默删除整个文件夹，包括卸载脚本自身。输入其他任意内容则取消，不删除任何东西。

卸载是不可逆的。删除范围是整个软件目录，workspace\ 里没导出的中间产物、reports\ 里没另存的报告会一起消失。删之前把要留的报告复制到别处。

11常见问题

双击后窗口一闪就没了

看 workspace\crash.log，里面会记下启动失败的原因和堆栈。整份日志可反馈。

拖文件没反应

多半是权限不一致：以管理员身份运行的窗口收不到普通权限资源管理器拖来的文件。让两边权限一致即可，或用「选择文件」。

提示某个工具缺失

去工具中心看检测结果。缺的工具可以一键下载或按指引安装；也可以手动指定可信的本机入口。配置了路径但依赖没装，调用时仍会报缺依赖。

报告里显示「已执行」，是不是说明有漏洞

不是。「已执行」只表示工具跑完了，退出码 0 也不等于没有漏洞。判定要看工具自己的输出和你的验证。

大文件卡住

超过 80 MB 的固件或镜像会跳过全文件正则，只对前 80 MB 做雕刻，这是防卡死的设计。超大文件建议先切分。

杀软报警

PyInstaller 打包的可执行文件偶尔会被启发式规则误判。放行前请自行核对文件哈希与来源，别在没核对的情况下加白名单。

12使用边界

下面几条不是免责套话，是会实际影响你合法性的边界。

  • 只用在你已获授权的目标上。比赛题目、主办方提供的靶机、你自己的实验环境。对任意第三方站点扫描或利用，即使只是「试一下」，也可能构成违法。
  • 启动时的勾选不代表授权。它只记录你声明了用途，不能替代比赛规则或站点所有者的许可。
  • WebShell 只做只读取证。软件从抓包里识别并解密菜刀、蚁剑、冰蝎、哥斯拉的通信，不生成马、不连接、不重放。
  • 攻击类自动化有明确上限。SQLMap 走低级别低风险、单线程、限速、不跟随重定向；目录与端口扫描用小词表；都不整站爬取、不导出数据库、不执行系统命令。
  • 商业软件自行解决授权。IDA Pro、Xshell 等需要你自备正版，本工具不提供破解版。

使用本工具产生的后果由使用者承担。

  • 无参数页面盲探：首页无表单、无查询串时，按 url/u/uri/link/src/target/redirect/next/image/file/path/host/ip/domain 等常见名逐个探，探针为 file:///etc/passwd、http://127.0.0.1/flag.php、1，命中即进入矩阵。

  • 伪协议：file:///var/www/html/flag.php、php://filter/convert.base64-encode/resource=… 自动解码后再扫 flag。
  • 报错注入：updatexml 每次取 24 字符、从 offset 1 分片拼接，直到出现 }，避免 32 字符截断导致的重复串。
