# 魔盒-CTF 架构（v3.7.0 基线 + v4.x 增量）

> 本文主体写于 v3.7.0；v4.x 的结构性改动集中记录在下面「v4.x 增量」一节与 `CHANGELOG.md`，
> 正文中出现的版本号以那一节为准。当前版本见 `ctfbox/__init__.py`。

- 版本：`4.1.0` / PE `4.1.0.0`（版本号唯一来源 `ctfbox.__version__`）
- 运行环境：Windows 10/11 + Python 3.13（源码运行）或 PyInstaller onedir 成品
- 界面：CustomTkinter；打包：PyInstaller（`CTFToolbox.spec`，输出 `CTFToolbox.exe`）

## v4.x 增量（相对 v3.7.0 基线）

| 主题 | 变化 | 位置 |
|---|---|---|
| 版本单一来源 | 只有 `ctfbox.__version__` 一处字面量；UI 标题、报告头、`result.json`、PE 版本资源全部派生，打包时自动生成 `version_info.txt` | `ctfbox/versioning.py`、`CTFToolbox.spec` |
| 运行产物治理 | 统一 `workspace/runs/<run_时间_进程号>/`，滚动保留最近 12 次；目录名用内容稳定哈希，不再受 `PYTHONHASHSEED` 影响 | `ctfbox/common.py`（`new_run_dir` / `prune_runs`） |
| 进程树隔离 | 外部脚本统一走 Job Object / killpg，超时连孙进程一起回收，输出强制 UTF-8 | `ctfbox/process_runner.py`、`ctfbox/rac/runner.py` |
| 编排成本阶梯 | 毫秒级确定性步骤全部排在 60~180s 深度子进程之前；命中强 flag（≥0.9）即跳过重模块 | `ctfbox/autopilot/orchestrator.py` |
| 脚本库排序 | `scriptlib.select()` 按 `timeout` 升序稳定排序，便宜的确定性脚本先跑 | `ctfbox/autopilot/scriptlib.py` |
| AI 开关粒度 | `conductor`（编排）/ `rerank`（重排）拆为独立开关，默认均关 | `ctfbox/ai/config.py` |
| 平台容错 | 非 JSON 响应统一抛 `PlatformError`；多附件题逐个尝试（≤3，命中即停） | `ctfbox/platforms/` |

## 一、总体结构


```
┌─────────────────────────────────────────────────────────────┐
│ GUI（ctfbox/ui_*.py，15 个标签页） / CLI（main.py 参数分派）   │
├─────────────────────────────────────────────────────────────┤
│ 责任说明闸门 ctfbox/responsibility.py + ui_consent.py        │
├──────────────┬──────────────┬──────────────┬────────────────┤
│ 一键分析      │ 一键梭哈      │ 赛事专项      │ Web 快速/深度   │
│ dispatcher   │ autopilot    │ competition  │ webauto/webattack│
│ + modules_*  │ + triage     │ 8 个模式      │ + autopilot     │
├──────────────┴──────────────┴──────────────┴────────────────┤
│ 公共层：识别器 identifier、工具管理 toolsmgr、脚本库、RAC     │
│ 平台层：platforms（CTFd / PolarCTF）                         │
│ 基础层：subprocess 静默调用、workspace 任务目录、audit 审计    │
└─────────────────────────────────────────────────────────────┘
```

设计原则：

1. **判型优先**：一键梭哈先判断主考点，再只执行有证据支撑的阶段，避免对每题遍历全部工具。
2. **确定性工具优先**：能用固定算法、正则、静态解析解决的，不调用大模型、不猜测。
3. **证据可追溯**：每个发现带 URL/文件、载荷摘要、响应片段、置信度与时间；每次 Web 请求写审计记录。
4. **不执行未知样本**：附件只做只读分析；加固/回滚脚本与检测用例只生成、不执行。
5. **缺工具如实标注**：Ghidra、Volatility、jadx、Playwright 等缺失时报告写明「未接入 / 已跳过 / 依赖缺失」，不伪造能力。

## 二、入口与责任闸门

### 2.1 入口

`main.py` 负责模式分派：

| 模式 | 入口函数 | 说明 |
|---|---|---|
| GUI | `ctfbox.ui_main.main()` | 启动责任说明窗 → 主界面 |
| `--cli` / `-c` | `run_cli()` | 批量附件分析 |
| `--auto` / `--v3` | `run_v3_auto()` | 一键梭哈（文件 / URL） |
| `--rac` | `run_rac()` | RAC 题目流水线 |
| `--webauto` / `--web` | `run_webauto()` | 只读 Web 取证 |
| `--webattack` / `--deep` | `run_webattack()` | 深度 Web 全自动 |
| `--pwn` | `run_pwn()` | ELF 静态定位与 ret2win 闭环 |
| `--platform` | `platforms.cli.main()` | 平台登录、列表、开实例、提交 |
| `--comp` | `competition.cli.main()` | 赛事专项八个子命令 |

### 2.2 唯一责任闸门

- `ctfbox/responsibility.py`：版本化的《软件责任说明》文本 + SHA-256；确认记录写入 `workspace/config/responsibility.json`。
- GUI：`ctfbox/ui_consent.py` 在每次启动时展示说明窗，必须勾选「我已逐条阅读并同意」才能进入；拒绝或关闭窗口直接退出。
- CLI：首次使用需 `--accept-responsibility`；`ensure_cli()` 在八个 CLI 分支统一拦截。说明版本变化后旧确认自动失效。
- 兼容参数：`--ctf-only`、`--i-own-this-target`、`--consent` 仍可传入，但不再强制、不再改变行为。

## 三、一键分析（dispatcher + modules_*）

流程：

```
输入文件/目录 → identifier 识别类型 → dispatcher 匹配模块 → 串行执行
             → 结果汇总 → 递归下钻嵌套容器（zip/rar/7z/图片内嵌/文档附件）
             → 报告（txt / html）与任务工作区
```

模块按能力拆分在 `ctfbox/modules_*.py`：编码与古典密码、哈希、对称/非对称、隐写、图片/音频/视频、流量包、WebShell 流量、逆向、Python 反编译、归档、DNS、日志、文档、蓝牙、车辆/题目专项、动态靶机利用等。源码、`.apk`、`.evtx` 等类型会自动触发赛事专项增强。

## 四、一键梭哈（autopilot）

### 4.1 首层判型

`ctfbox/autopilot/triage.py`：

- **文件判型** `file_triage()`：按文件类别与子类型、文本特征（PHP 源码、哈希、无空白 XOR/编码密文、像素矩阵、零宽字符）、二进制特征（PNG/JPEG/GIF、PCAP、pyc、ELF 保护位与符号、文档/取证镜像、高熵）评分。
- **Web 判型** `web_triage()`：按表单/上传点、参数名（`file`/`url`/`cmd`/`q`/`id` 等）、序列化线索、PHP 源码、技术栈、题面关键字、URL 路径分段累计评分；登录与上传阈值更高并优先执行；无证据回退 SQLi + XSS/JWT/IDOR；反序列化仅在确有序列化/源码/Java/PHP 证据时执行。
- 输出：`kind / category / subtype / confidence / evidence / stages / scripts / skipped`。

### 4.2 编排

`ctfbox/autopilot/orchestrator.py` 按判型结果选择阶段，文件链的阶段包括：

1. 类型识别、哈希、分块熵、strings；
2. 单字节 / 重复密钥 XOR + crib 反推；
3. 编码套娃解码（Base 全家族、ROT、Morse 等）；
4. 归档与递归下钻（zip/rar/7z，含 ZipCrypto 口令候选恢复）；
5. 图片/音频隐写（EXIF、PNG 块、多比特 LSB、尾部数据、FFT、cloacked-pixel）；
6. 哈希识别与弱爆破；
7. PE/ELF 静态分析、Ghidra headless 反编译（主证据）、r2 复核；
8. 对称密码密钥候选试解（RC4/AES/DES/3DES）；
9. RSA / ECC / 异常曲线 HNP；
10. 候选 flag 汇总与置信度评估。

Web 链的阶段由 `exploit/engine.py` 提供：指纹、SPA 渲染、登录门槛识别、只读入口探测，以及反序列化、上传、SQLi、命令注入、SSTI、SSRF、XXE、LFI、XSS、CSRF、Cookie、JWT、IDOR、弱口令等利用阶段。

### 4.3 确定性工具

`ctfbox/autopilot/tools/`：

| 文件 | 能力 |
|---|---|
| `archive.py` | zip/rar/7z 解包、嵌套容器、加密 ZIP 口令候选 |
| `binary.py` | PE/ELF 静态分析、保护位、符号与字符串 |
| `ghidra.py` | `analyzeHeadless` 自动分析并导出 C 伪代码 |
| `crypto.py` | RC4/AES/DES/3DES 密钥候选试解 |
| `rsa.py` | 共模、小指数、Fermat、已知 p/q/d、残缺密文 |
| `ecc.py` | 异常椭圆曲线恢复与多维 HNP |
| `stego.py` | 图片/音频隐写与 cloacked-pixel |
| `webprobe.py` / `webexploit.py` | 只读探测与利用阶段 |
| `scriptrun.py` | 脚本库预检与静默执行（解释器、依赖、参数） |
| `scriptlib.py` | 按判型从白名单选脚本并生成参数 |
| `hash.py` / `codes.py` / `xor.py` / `z3tool.py` / `deepmisc.py` | 哈希、编码、XOR、约束求解与杂项 |

### 4.4 工作区与 WP

`ctfbox/autopilot/workspace.py` 为每个任务建独立目录：

```
workspace/tasks/<时间>_<类型>_<目标>/
├─ input/          输入副本
├─ artifacts/      提取物、验证样本
├─ logs/run.log    运行日志
├─ evidence.jsonl  证据链
├─ result.json     结构化结果
└─ report.md / wp.md
```

WP 固定格式 `mohe-wp-v1`（`ctfbox/autopilot/wp.py`），六章节：题目信息 / 信息收集 / 解题过程 / Flag / 修复建议 / 附录（证据与审计）。文件类 WP 另含「首层判型（主考点路由）」小节。未命中的阶段写「未确认」，不编造步骤。

### 4.5 本地模型裁判（可选）

`ctfbox/ai/` 提供确定性流程之后的调度补充，模型不直接产出 flag：

- `config.py`：`ai_config()` 合并默认值、`ai_config.json` 与 `MOHE_AI_*` 环境变量；`_discover()` 在 `models/*.gguf` 与 `runtime/llama/{cuda,cpu}/llama-server.exe` 中定位资源；`ai_enabled()` 要求开关、模型与运行时同时存在。
- `backend.py`：`LlamaServer` 启动 `llama-server`（`--ctx-size`、`--n-gpu-layers auto`、`--fit-target`、`--parallel 1`，无窗口），轮询 `/health` 就绪；`ngl=auto` 由 llama.cpp 按实际可用显存自动拟合层数并强制保留 `vram_reserve_mb`（默认 4096 MiB），GPU 启动失败依次回退 `ngl=0` 与 `runtime/llama/cpu`；`complete()` 走 `/completion` 并支持 `grammar`。
- `conductor.py`：模型为 `Qwen2.5-3B-Instruct-abliterated` Q4_K_M（1.93 GB，魔搭 `huihui-ai`，apache-2.0）。输入是工作区状态（类型、`T0…Tn` 目标及各自 `allowed` 动作、已有候选、已尝试动作、备注），输出由 GBNF 约束为 `{"action","target","depth","reason"}`；`ACTIONS` 白名单、目标编号、depth 1–3 与目标类型适用性再校验；`_dispatch()` 只调用既有 `autopilot/tools`；最多 `max_decisions`（默认 3）次，已有 ≥0.9 置信候选则跳过。
- 接入：`AutoPilot.__init__(ai=None)`；`run_file()` 收尾调用 `_ai_conductor()`；GUI「本地模型裁判」与 CLI `--ai` 控制。任一环节失败均只写日志并回退，不改变确定性结果。
- 资源开销（实测）：`offloaded 37/37 layers`，CUDA 模型缓冲 1834.83 MiB + KV 144 MiB + 计算缓冲 84.51 MiB ≈ 2063 MiB；`fit-target=4096` 拟合后保留 4979 MiB 空闲显存。

## 五、Web 全量利用

- `ctfbox/autopilot/exploit/client.py`：统一请求客户端。只接受 http/https 绝对地址，拒绝 URL 内用户名口令；限速、请求预算、逐请求审计。
- `ctfbox/autopilot/exploit/engine.py`：页面解析（表单、链接、参数）、阶段执行、flag 提取与验证。
- `ctfbox/autopilot/exploit/payloads.py`：反序列化、SQLi、命令注入、SSTI、SSRF、XXE、LFI、XSS、JWT 等载荷。
- 审计：任务 `audit.jsonl` 与全局 `workspace/audit/audit-YYYYMMDD.jsonl`，记录目标、工具/阶段、payload 摘要（SHA-256 + 前 200 字符）、响应状态与时间。

## 六、赛事专项（competition）

| 模块 | 能力 |
|---|---|
| `memory.py` | Volatility 3 三形态探测；Windows/Linux 插件；明文扫描与可疑点 |
| `traffic.py` | TCP 重组、HTTP 对象还原、DNS 隧道评分、文件雕刻 |
| `mobile.py` | AXML/DEX/证书/凭据、导出组件与权限审计、jadx 反编译 |
| `codeaudit.py` | PHP/Java/Python 危险点与污点链，证据到 `文件:行号` |
| `baseline.py` | Windows 只读检查、Linux rootfs 离线检查、加固/回滚脚本生成与语法校验 |
| `logtime.py` | EVTX/在线收集、Linux 日志、暴破与横向线索、CSV 时间线 |
| `defense.py` | WAF/NGFW 清单、无害检测用例、加固前后模板与基线对比 |
| `cli.py` | `--comp <memory\|traffic\|mobile\|codeaudit\|baseline\|logtime\|defense\|compare> ...` |

所有模块只读本地文件；加固/回滚脚本与检测用例只生成、不执行、不发送。

## 七、平台闭环（platforms）

`ctfbox/platforms/ctfd.py` 提供 `CTFdPlatform`，兼容 PolarCTF：

- 登录态保存在 `workspace/platform/<平台>.json`，支持 Cookie 文件或账号口令登录；
- 题目列表、题目详情、开实例与就绪等待；
- `--solve` 调用本地一键梭哈，得到高置信 flag 后自动提交，记录 `correct` / `already_solved` / `wrong`；
- WP 归档到 `workspace/wp/`。

## 八、RAC 与脚本库

`ctfbox/rac/`：

- **题目流水线**：题目描述/参数 + 附件 → 题型与参数识别（RSA 参数、host:port、哈希、密文、账号口令）→ 脚本库静态解析评分 → 子进程静默执行 → 强模式提取 flag → top-N 候选降级。
- **侦察自动化**：TCP 端口扫描、HTTP 探测、目录探测。
- **远程执行**：SSH 主机清单批量执行（paramiko，并发可调）。
- **Oracle RAC 巡检**：SSH 只读命令集汇总报告。
- **RPA 会话**：JSON 步骤表驱动 HTTP 会话，自动登录/CSRF 回填/提交 flag。

`scripts/library/` 共 88 个脚本与速查表（69 个 Python 脚本），单文件自包含，绝大多数支持 `--selftest`，同时是 RAC 与一键梭哈的装配来源。

## 九、扩展方式

- **新增分析模块**：在 `ctfbox/modules_*.py` 实现处理函数，并在 `dispatcher.py` 注册扩展名/类型映射。
- **新增自动阶段**：在 `autopilot/tools/` 增加工具模块，在 `orchestrator.py` 注册阶段，并在 `triage.py` 增加判型证据与阶段选择规则。
- **新增脚本**：放入 `scripts/library/<类别>/`，文件头写明方向、简介、用法、依赖；`scriptlib.py` 会自动解析参数并纳入评分。
- **新增平台**：在 `ctfbox/platforms/` 实现登录、列表、详情、开实例、提交接口，并在 `cli.py` 注册平台名。
- **新增赛事子命令**：在 `ctfbox/competition/cli.py` 注册子命令，在 `main.py --comp` 分支透传。
